# HPC-0002 – Kennung `kalk` als Beispiel-Erweiterung reservieren

**Typ:** Registrierung · **Klasse:** Erratum (keine normative Wirkung) · **Status:** umgesetzt
**Eingereicht:** 2026-10-11 (Paket S4) · **Entschieden:** 2026-10-11 (Registrar = Herausgeber, Phase A; Registrierungen ohne normative Wirkung brauchen keine Einspruchsfrist nach HPG-GOV-003, weil kein normativer Text geändert wird)

## Anlass

Teil 2, Abschnitt 7 braucht eine Beispiel-Erweiterung mit fester Kennung, die nie an einen echten
Anbieter vergeben wird (wie `example.org` nach RFC 2606).

## Eintrag

| Feld | Wert |
|---|---|
| kennung | `kalk` |
| id | `https://kalk.example.org/ns/hp-ext/kalk` |
| owner | fiktiver Anbieter (Beispiel in Teil 2, Abschnitt 7) |
| contact | keiner (Beispiel) |
| url | `https://kalk.example.org/hp-ext/kalk/1.2/` |
| status | `beispiel` |
| registered | 2026-10-11 |

Zusätzlich steht `kalk` in der Liste der reservierten Kennungen (Teil 2, Abschnitt 8.3), damit der
Registrar sie nie vergibt.

## Prüfung durch den Registrar

- Kennung frei: ja (erste Registrierung überhaupt).
- Syntax nach HPG-EXT-001: `kalk` entspricht `^[a-z][a-z0-9]{1,15}$`.
- URI unter Kontrolle des Anbieters: `example.org` ist nach RFC 2606 reserviert; für ein Beispiel
  zulässig, für einen echten Anbieter nicht.
- Beschreibung öffentlich: Teil 2, Abschnitt 7.3.
- Keine Verletzung von HP-VERS-007: Beispiel enthält keine Skripte, keine externen Verweise.

## Auswirkung

Keine normative Wirkung. Registry-Datei und Tabellen 8.3/8.5 geändert; mechanische Prüfung grün.
