# HPC-0004 – Dokumentdaten-Kanal: `window.parent` in Teil 1, Abschnitt 8.1 widerspricht dem Vorfilter HPR-SBX-016

**Typ:** Erratum · **Klasse:** Erratum · **Status:** in Frist
**Eingereicht:** 2026-10-12 (Paket S7) · **Angekündigt:** 2026-10-12 · **Einspruchsfrist bis:** 2026-10-26 (14 Tage, HPG-GOV-003)
**Entscheidung:** ausstehend (Herausgeber, Phase A)

## Anlass

Teil 1, Abschnitt 8.1 sagt: „Die Komponente sendet an `window.parent` mit `targetOrigin` `"*"`“.
HPR-SBX-016 (Teil 1, 5.6) meldet jedoch jeden Eigenschaftszugriff `parent` auf `window`,
`globalThis` oder `self` als Verstoß. Eine Komponente, die den Wortlaut von 8.1 befolgt, fällt
damit durch den Prüfer; nur die Schreibweise ohne `window.`-Präfix (`parent.postMessage(…)`) wird
angenommen. Entdeckt beim Schreiben der Beispielkomponente `x-baubuero-aufmass` für das
Umsetzer-Handbuch ([`docs/belege/S7/pruefbericht.md`](../../belege/S7/pruefbericht.md), Frage 6).

## Betroffene Zusage

Zusage 2 (lebendig statt statisch): weder gestärkt noch eingeschränkt; es geht um die
Widerspruchsfreiheit der Regel, nicht um ihre Reichweite.

## Betroffene Anforderungen

- **HPR-SBX-016** (Teil 1) – geändert: `parent` wird aus der Liste der gemeldeten Eigenschaftszugriffe
  gestrichen, sofern der Zugriff ein `postMessage`-Aufruf ist (`window.parent.postMessage(…)`);
  `top` und `opener` bleiben Befunde.
- **Teil 1, Abschnitt 8.1** – ergänzt um den Hinweis, dass beide Schreibweisen (`parent.postMessage`
  und `window.parent.postMessage`) zulässig sind.
- **HP-SBX-007, HP-SBX-008** (Teil 0) – unverändert.

## Änderungstext (Vorschlag für Teil 1, HPR-SBX-016, Satz zur Prüfung)

```
… `open` auf `window`, `__TAURI__`, `__TAURI_INTERNALS__`, `ipcRenderer`, `require`, `process`,
`eval`, `Function` als Aufruf, `importScripts`, `Worker`, `top` und `opener` als Eigenschaftszugriff
auf `window`/`globalThis`, sowie `parent` als Eigenschaftszugriff auf `window`/`globalThis`, wenn
darauf nicht unmittelbar `.postMessage(` folgt, sind Befunde. …
```

## Kompatibilität

Erratum: kein Dokument wird ungültig; Komponenten, die bisher nur mit `parent.postMessage`
bestanden, bestehen weiter. Prüfer melden nach der Änderung einen Fall weniger.

## Auswirkung je Subjekt

| Subjekt | Änderung |
|---|---|
| Dokument | keine |
| Erzeuger | Komponenten dürfen `window.parent.postMessage` schreiben |
| Lesesystem | keine |
| Prüfer | Vorfilter HPR-SBX-016 um die Ausnahme ergänzen |
